# 海湾沙盘与图解经营

本轮以普通经营游戏玩家为对象，让供电问题、投资取舍和执行结果可以直接看见。建设、自动调度、物理电网和可信观测继续构成玩法，复杂系统随经营过程逐步开放。

## 已确认的视觉方向

以下为视觉概念图，图中建筑细节和示例数值不代表实际游戏状态：

- [日间经营](design/concept-overview.png)：大供电比例条、明确缺口、地图端点和下一步。
- [储能投资](design/concept-storage.png)：设施缩略图与共同尺度的功率、时长、效率比较。
- [风暴处置](design/concept-storm.png)：夜间可读地图、已核实与未知状态、现场队执行进度。

界面沿用深海蓝面板、奶油白文字、薄荷绿电力、琥珀关注及珊瑚红缺口。主要结果、标题、普通标签和解释分级显示；图表同时提供单位、数值和形状编码。海湾与设施保留画面主体位置。

## 行为要求

- 主界面回答是否缺电、缺口大小、现金与运营收益、当前主要问题。
- 地图、诊断卡、对象与操作队列共享目标，避免重复告警及跨页寻找设施。
- 发电区分额定、可用和实际输出；储能区分 MW、MWh、标称时长和当前可持续时间。
- 当前值、未提交草案、在途设置与真实回执分别表达。等待完成不得跳过中途拒绝、供电恶化或目标中断。
- 账本默认解释收入和成本，完整明细可以展开；报价参考与真实成交历史分开。
- 新经营流程循序开放接网、昼夜、清洁与成本、备用、跨城。自由沙盘和历史战役保留。
- 探索区域不立即承担新城市的供电责任。城市规划、建设与正式开通服务分别执行。
- 旧存档维持原有资产、策略、解锁和在途任务；不能准确映射的策略保留为旧版自定义。

## 数据边界

图表只使用公开运营反馈、额定参数、可信遥测和现场记录。未知不等于零，不得绘制未核实的故障、功率或健康；过时读数注明记录时间。历史随实际仿真时间采样，打开面板、悬停与刷新不产生历史或费用。操作前后变化属于观测对照，需要同时展示同期事件，不能冒充独立因果预测。

## 验收

覆盖 1280×720 至 1920×1080、100% / 125% / 150%、夜间风暴、高对比和减少动效。检查供需比例、未知读数、队列拒绝、共同尺度比较、账本守恒、策略生效与存档迁移，并以 Godot 实际渲染目视复核。自动测试之外，真人任务观察用于验证理解速度和操作效率，不以截图通过代替。
