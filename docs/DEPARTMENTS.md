# 同一电网，七种职业视角

本轮采用设计报告推荐的组合：沙盘使用「统一调度桌 + 部门视角」，经营／运维／发展中心承担深入配置，事故以证据卡与恢复复盘呈现。切换视角不更换世界、不结算时间、不代替玩家执行动作，也不改变选中对象的身份。

## 从主界面开始

顶部保留供电比例、已供／需求、MW缺额、现金、小时净收益和时间。下方七个视角共用一张地图；小窗口使用视角选择器。点「部门总览」，或右侧「部门」页，查看该职责的三项主要指标、最多五条优先事项和关联视角。其余指标与六项系统结果按需展开。

| 视角 | 首先回答的问题 | 地图重点 | 深入操作 |
| --- | --- | --- | --- |
| 运行 | 现在供得上吗，先处理谁？ | 已核实潮流、80%以上负载、缺电与医院反馈 | 供电诊断、对象操作、执行队列 |
| 规划 | 后续容量、接入与备用怎样准备？ | 电力网络、待开通的服务对象 | 24小时预测、三方案、单设施／线路退出推演 |
| 运维 | 队伍和备件先用在哪里？ | 已知设备状态与公开服务影响 | 真实现场队、待派工、检修与回执 |
| 市场 | 供电选择如何影响价格与现金？ | 联络站净交换、受限线路 | 交易、电价、合约、储能、现金分类账 |
| 资产 | 哪些已知健康状况值得优先处置？ | 健康与关键负荷邻接关系 | 健康×公开影响矩阵、继续／检修／更换比较 |
| 客户 | 谁在失供，关键服务受何影响？ | 街区反馈、医院、服务阶段 | 可靠性、事件贡献、复盘、街区与微电网 |
| 数字 | 看得见、信得过、控得了吗？ | 独立通信拓扑、可信度与未知状态 | 通信路径、观测、安全与延迟控制 |

六项结果分别为供电、运行安全、经营、清洁供电、设备状态和可观测性。风险排序保留影响、紧迫性、证据来源及适用动作；没有不可解释的综合总分。医院失供优先于一般用户反馈；故障、超载和过时读数只在已有证据范围内呈现。

## 同一个行动闭环

从风险卡展开「原因、证据与下一步」，定位同一个设施或线路。对象检查器根据当前视角解释后果，专业控制仍通过原有提交路径执行。公开拓扑已经能证明未接网时，可以直接开始接线；需要核实的状态保持问号。

设施和线路检查器提供运行／退出影响比较。投运资产风险管理后，还可比较继续运行、所选检修和更换。发展中心使用独立副本计算同一24小时内的已供与失供MWh、净现金、最大线路负载、最低电压、最低功率余量、清洁供电、本地排放及医院负荷点影响。差分与三张图使用共同口径和标尺。

检修方案调用副本中的真实工单规则，包含费用、备件、出行、队伍占用和停运。没有足够现金、备件或重复任务时会拒绝。没有自动投运，也不会因为比较而派出真实队伍。回到对象控制提交后，仍须等待延迟执行与真实回执。

预测明确列出未知健康、储能、电表和天气的假设；运行状态、草案或会话变化使旧结果过期。电量是MWh，瞬时功率是MW；比例变化使用百分点。本地排放不包含未知的外购电隐含排放，参考清洁占比也不作为排放认证。当前游戏使用24小时经营时域，未伪造1／5／10年人口或资产现金流。单故障情景沿用有功与压降近似，不声称是完整AC或工程N−1安全校核。

## 现场队与资产信息

统一队列包含数字命令、现场设置、原有抢修、资产检修和微电网切换。两条泳道只显示已经占用队伍的任务；待派工单独列出，不会被误画成第三支队伍。在途、等待、执行、拒绝和取消分别显示。原始工单没有保存完整计划工期时，只显示确知的剩余时间。

资产矩阵的两轴分别是已核实健康和公开影响代理。后者使用设施用途、线路端点及关键负荷邻接关系，不能解释成真实故障概率或停电范围。当前未知与过时记录不进入当前健康矩阵；历史巡检值单独标识，不能当成实时遥测。点击圆点仍定位原设施／线路。

## 可靠性与事故复盘

客户与运行视角可展开可靠性趋势、SAIDI贡献和事故证据。趋势可切换平均停电时长、平均停电次数、CMI及ENS，每次只绘制一种单位。点击贡献条展开造成该贡献的事件，再定位受影响负荷。恢复复盘保留持续时间、实际失供电量、已核实事实与真实操作回执，不凭时间上的先后关系宣称根因。

游戏没有逐户人口电表，因此采用明确的**负荷点口径**：每个已开通服务的住宅街区、工业园区或医院计一点，不等于居民户数。供电低于需求98%记录一次持续失供，恢复后再次失供另计。分母是窗口累计纳入点数，拆除不抹除过去责任。

| 指标 | 本游戏口径 |
| --- | --- |
| CMI | 失供点分钟之和，单位「点·分钟」 |
| SAIDI | CMI ÷ 窗口累计纳入负荷点，分钟／点 |
| SAIFI | 中断事件次数 ÷ 窗口累计纳入负荷点，次／点 |
| CAIDI | CMI ÷ 中断事件次数，分钟／次 |
| ENS | 全部实际供需缺额积分，MWh；包含98%阈值内的小缺额 |

事件明细最多200条、小时趋势最多96条，归档汇总继续保留累计贡献。新窗口尚无样本时显示待积累。schema9保存进行中事件、口径、分母、历史与汇总；schema1—8从载入时刻建立新窗口，不补造未曾记录的历史。采样遵循实际仿真步长，最长约3游戏分钟。

## 信息深度与验证

「入门／运营／工程」可在视角栏或显示设置中切换，独立保存为个人偏好。入门先显示结果和下一步；运营展开单位与来源；工程额外显示观测年龄和模型限制。三档不改变仿真难度、研究解锁或历史战役能力。

专项测试位于 `test_attention_model`、`test_unified_jobs`、`test_reliability_metrics`、`test_decision_delta` 和 `test_department_ui`。它们分别检查纯查询和未知信息边界、共享队伍、累计守恒与旧档迁移、同源差分与过期状态，以及真实控件输入和响应式布局。`render_departments.gd`生成实际界面矩阵，覆盖1280×720与1440×900的100%、125%、150%缩放。

这些检查可证明数据与交互闭环，不能代替外部玩家的理解测试。建议试玩时记录：30秒内能否分清发电不足与输送瓶颈、能否识别未知故障、能否找到恢复医院但增加成本的方案，以及是否会把已排队误认为已生效。
